Notes on the marginal likelihood, Occam's razor, and why the marginal likelihood is not always aligned with model selection and generalization.

Marginal Likelihood

Probability that would generate dataset D with model M if randomly sampled from a prior over its parameter p(w).

P(D|M) = ∫ P(D|M, w) P(w|M) dw

Marginal likelihood → likelihood formed by marginalizing parameters w.

Maximizing marginal likelihood → empirical bayes, type II maximum likelihood estimation.

Decompose marginal likelihood:

P(D|M) = ∏in P(Di | D<i, M)

How good a model is at predicting each data point in sequence given every data point before it.

Occam Factors

argument of integral → posterior P(w|D, M) upto constant of proportionality.

Assume, posterior is relatively concentrated around ŵ = argmaxw P(w|D, M) → perform rectangular approximation of integral, as height of posterior times width σw|D to find.

P(D|M) ≈ P(D|ŵ, M) · σ(w|D) / σw

P(D|ŵ, M) → data fit

σ(w|D) / σw → occam factor = width of posterior / width of prior

If posterior contracts significantly from prior, there will be large Occam penalty, leading to low LML.

Occam's Razor

ML automatically encapsulates notion of Occam's razor.

If model can generate small number of datasets, it will generate those dataset with high probability, since marginal likelihood is normalized probability density. (Simple Model)

By same reasoning, a model which can generate many datasets can't assign significant probability density. (Complex Model)

For given dataset, marginal likelihood will automatically favour most constrainted model thats consistent with data. (Simple Model)

Example: suppose we have f1(x, w) = w1x, f2(x, w) = ∑i=1100 wixi with P(w) = N(0, I).

In both case, data given by straight line with particular slope. Both models have parameter consistent with data, first model more likely to generate dataset.

Hypothesis Testing

ML → a mechanism to select between fixed hypothesis, even if each hypotheses entirely consistent with our observations and prior odds are equal.

Hypothesis Testing (Detail)

Hypothesis Testing → process of evaluating competing claims about data-generation process based on observed sample data.

Does Data support a default assumption? or is evidence strong enough to favor distinctive alternative explanation (HA).

Instead of evaluating model's predictive accuracy after it's been trained, LML in hypothesis testing answers → what's probability that model generated the training data? It naturally penalizes unwarranted flexibility.

Evaluating Priors vs Posteriors

Hypothesis Testing → evaluates fixed hypothesis (prior) before it combines data. Not interested in how model updates based on data, and then deciding whether update model is correct.

Model Selection → evaluates posterior (model after it has been updated with data) to determine which provides better generalization.

LML → pertinent to hypothesis testing, but not generally well aligned with model selection.

Hyperparameter Learning

LML → used to learn hyperparameter of prior to find argmaxθ p(D|θ)

p(D|θ) = ∫ p(D|w) p(w|θ) dw

Traditionally, hyperparameters tuned using cross-validation; testing various combinations on withheld subset of data to see which performs best. As number of hyperparameters grow, testing all combinations becomes computationally crippling.

Instead of relying on brute force cross validation the LML can evaluate and adjust hyperparameter using training data alone. LML can be applied where std. cross validation fails.

Instead of optimizing data fit, LML bypasses overly complex fit, choose hyperparameter value that makes model's underlying distribution most likely to have generated training data.

Gaussian Process → demonstration of LML Hyperparameter Learning.

Example: set a hyperparameter like length scale of a mathematical kernel. Std. approach ⇒ select a small value that would perfectly memorize the data → overfitting.

Constraint Learning

To automatically identify most restrictive model structure that still accurately explains observed data.

Learners such as Maximum Likelihood are naturally biased towards more flexible, complex models, the LML provides a consistent estimator for identifying inherent constraints.

Typical learners are never incentivized to select for constraints because a constrained model is special case of more flexible one. A more flexible model can always increase its likelihood by expanding its parameters.

LML counterbalances by automatically selecting the most constrained solution that fits data + collapses to true value of constraint using training data alone, in limit of infinite observations.

Bayesian PCA → while marginal likelihood always selects largest possible subspace dimensionality, LML effectively estimates true lower dimensional subspace.

Symmetry Learning → automatically learns symmetries such as rotational invariance.

Pitfalls of Marginal Likelihood

Conceptual challenges w/ marginal likelihood → conditional marginal likelihood → partial remedy.

ML → probability that prior model generated training data. Different from how likely is posterior, conditioned on training data, to generate withheld points drawn from same distribution.

Although ML → proxy for generalization, to answer deciding whether model would provide good generalization performance:

If after observing data, prior A → posterior B and prior C → posterior D, can be a case when same data are less probable under B than D and D provides better generalization on fresh points from same distribution even if prior A explains the data better than C.

Prior over diffuse set of solutions, will observe significant posterior contractions (as many solutions provide poor likelihood), while marginal likelihood can be poor → posterior can be perfectly reasonable.

Understanding Why marginal likelihood will be poor

  1. Diffuse Prior
  2. Occam Factor Penalty = width of the posterior / width of the prior
  3. Product Decomposition of Marginal Likelihood

Product decomposition of ML → first terms → low probability density, even if posterior updates quickly to become good description of data.

Different prior, allocates mass significantly to moderate consistent solutions → giving much higher marginal likelihood but posterior which provides poorer generalization.

ML → product of sequential predictions. A diffuse prior (broad + many possibilities) → poor initial predictions because it hasn't narrowed down 'truth' yet → early low prediction tank total LML score. Even if model learns quickly and becomes extremely accurate after few data points, can't erase penalty paid for first few bad guesses.

Different model → prior less wrong on average → allocates more probability to more consistent solutions → model has higher LML because better initial guesses, even if posterior might not be accurate that first.

Marginal Likelihood Optimization and Overfitting

Marginal Likelihood Optimization for hyperparameter Learning → type-II maximum likelihood or Empirical Bayes → special case of model selection.

ML → effective for hyperparameter tuning → can be prone to underfitting and overfitting.

Overfitting by ignoring uncertainty

overfit marginal likelihood ⇒ overfit likelihood. Likelihood for one model can always be seen as marginal likelihood for another model.

Misconception → bayesian nature of LML automatically protects a model overfitting.

Search Space Trap

If your hyperparameter search space includes a prior model is highly concentrated around specific overfit solution, LML will favor it.

Such models appear simple and constrained because it can only generate one specific dataset, resulting in high LML score despite zero predictive power for new data.

Gaussian Process

By parameterizing the mean function of the Gaussian Process with neural network (MLP) when they optimized the LML to learn the MLP parameters, the model perfectly fits the training points but provided wildly overconfident and inaccurate predictions for any data outside that region.

Why Occam factor fails? In specific GP case, the occam factor which usually penalizes complexity — doesn't account for parameters in mean function leaving model unprotected from conventional overfitting.

Underfitting in Hyperparameter

ML ⇒ can lead to underfitting, particularly when dealing with small dataset. supporting a good solution (one that generalizes well), a prior might have assign probability mass to many other solutions that are highly unlikely to generate training data.

Weight Norm: Imagine a scenario, where best weights for generalization have norm (w*) but there are simpler weights with small norms that provide moderate fits to data.

LML Bias: LML will favor small norm, mediocre parameter because it doesn't want to pay probability cost of broadening the prior enough to including high performing larger norms.

Pitfalls → highly dependent on how much data you have.

Small Data → LML → most vulnerable, highly influenced by initial prior assumptions and cost of moving away from them.

Large Data → more data → observed → likelihood signal ↑. Signal for correct parameter dominates → underfitting disappears.

Conditional Marginal Likelihood

Using product of decomposition of ML, LML can be:

log P(D|M) = ∑i=1n log P(Di | D<i, M)

Each term log P(Di | D<i, M) → predictive log-likelihood of the data point Di under the Bayesian Model Average after observing the data D<i.

terms for i close to n are clearly indicative of generalization of model to new test data → train on available data and test on unseen data. Other hand, small i have equally large effect on the marginal likelihood but may have little to do with generalization.

Early Data Points (small i)

first few predictions rely heavily on prior because model hasn't seen much data. If prior is diffuse, early predictions will be poor, drastically dragging down LML score.

Later Data Points (i close to n)

By time, model is predicting final data points, it has essentially been trained on previous data; later terms are highly indicative of true generalization.

Inspired by reasoning, → consider Conditional Log Marginal Likelihood (CLML). CLML → fixes by simply dropping first few terms of sequence. drop first (m-1) terms of the LML decomposition, to obtain the metric that is more aligned with generalization.

establish a cut-off point, m and only measures the model's predictive performance after it has chance to learn initial m-1 data points.

∑i≥m log P(Di | D<i, M) = log P(D≥m | D<m)

ignoring cost of learning that occurs before cutoff m, the CLML transforms into a metric more aligned with actual generalization performance.

Advantages of CLML

Addresses underfitting: for small datasets, the std. LML often underfits → reluctant to pay probability penalty required to move away from prior toward best parameter. CLML evaluates performance based on updated posterior P(w|D<m) which is re-centered away from prior - free to select parameters that provide superior generalization.

Easier to estimate: Std. LML → difficult to calculate because it requires integrating over prior.

CLML → ∫ P(Dm:n | w) P(w | D1:m-1) dw

Samples from posterior (narrowed down) rather than broad prior, much easier to estimate using Monte Carlo sampling.

Scalability: compared to traditional cross validation, CLML is more scalable and can be easily used to optimize thousands of hyperparameters simultaneously.

Authors → rational and applications are different → motivated by understanding how marginal likelihood can be fundamentally misaligned with generalization. Don't consider prior sensitivity a deficiency of ML, since ML is generating the probability that data is generated from prior. Expect CLML to address issues, except overfitting, since CLML optimization still fitting to withheld points.

Marginal Likelihood is not aligned with Posterior Model Averaging

Bayesian Inference → performance of Bayesian Model Average → integrate out parameter according to posterior, to form predictive posterior distribution.

P(d*|D, M) = ∫ P(d*|w) P(w|D) dw

d* → test datapoint.

Instead of using single setting of parameters combine the prediction of models corresponding to every setting of parameters weighting these models by posterior probabilities.

Misconception

Because marginal likelihood (LML) integrates over all parameters, McKay (1992d) argues that it is a good measure of 'plausibility of entire posterior ensemble'.

Decomposing LML using the evidence lower bound (ELBO)

log P(D|M) = log P(D) = ∫w log[P(D)] P(w|D) dw
           = ∫w log[ P(w, D) / P(w|D) ] P(w|D) dw
           = ∫w log[ P(D|w) P(w) / P(w|D) ] P(w|D) dw
           = ∫w log[P(D|w)] P(w|D) dw
             − ∫w log[ P(w|D) / P(w) ] P(w|D) dw
           = Ew~P(w|D)[ log P(D|w) ] − KL( P(w|D) ‖ P(w) )
           = expected sample likelihood − Occam Factor

Occam Factor Penalty

Occam Factor → ratio of width of posterior to width of prior. model requires wide prior to include correct solution but data eventually dictates a narrow posterior → pays massive penalty for uncertainty at start.

LML → may prefer → mediocre model with narrow prior thats less wrong rather than superior model stretched wide to find truth.

LML suffers ⇒ assign mass parameter that are unlikely to generate the data in order to reach parameter that are likely to generate data.

ML → integral of likelihood times prior. prior must integrate to 1, any probability mass → finite source. to reach parameters far away (weight with large norm) have to broaden prior distribution to give more weight.

broaden prior to include high performing but distant parameters ⇒ forced to assign probability mass to a vast volume of other parameters in between. Intermediate parameters → completely inconsistent w/ data and provide a very poor fit.

total probability mass is fixed → spreading across empty space reduces probability density assigned to actual good parameters.
